# data-lineage-impact-analyzer 示例

## 适用场景

字段、表、指标或任务准备变更，需要提前判断会影响哪些下游和业务方。

## 示例输入

```text
请用 data-lineage-impact-analyzer 评估下面这个字段下线变更。

变更对象：dwd_order_detail_d.old_channel_id
变更类型：字段下线。
原因：渠道归因统一切换到 channel_id_v2。
计划时间：2026-06-10 起停止写入 old_channel_id，2026-06-30 删除字段。
已知下游：
- ads_channel_gmv_1d 使用 old_channel_id 聚合渠道 GMV
- 经营日报渠道模块读取 ads_channel_gmv_1d
- 渠道投放复盘 SQL 中有历史查询使用 old_channel_id
希望输出：影响等级、兼容方案、通知对象、上线前检查和回滚条件。
```

## 预期输出

```markdown
## 影响评估结论

这是一个 P1 级口径变更风险，不应直接删除字段。建议至少保留 20 天兼容期，并在下游表切换到 channel_id_v2 后再删除。

## 影响清单

| 对象 | 类型 | 影响等级 | 影响说明 | 处理建议 |
| --- | --- | --- | --- | --- |
| ads_channel_gmv_1d | 下游表 | P1 | 渠道 GMV 聚合字段会变化 | 改 SQL 并双跑校验 |
| 经营日报渠道模块 | 看板/报表 | P1 | 渠道趋势可能出现断点 | 标注口径切换日期 |
| 渠道投放复盘 SQL | 临时分析 | P2 | 历史查询会失效 | 通知分析同学替换字段 |

## 风险与缓解措施

- 双跑 old_channel_id 和 channel_id_v2 聚合结果。
- 保留字段到 2026-06-30，避免临时查询直接失败。
- 删除前确认近 7 天无下游读取。
```

## 使用说明

这个示例展示如何区分已知影响和待确认影响，并给出兼容、双跑、通知和回滚建议。
