# metric-definition-reviewer 示例

## 适用场景

团队要定义或修改指标，需要提前检查口径漏洞和边界条件。

## 示例输入

```text
请用 metric-definition-reviewer 审查这个指标：

指标：新用户 7 日首购转化率
当前口径：注册后 7 天内完成支付的新用户数 / 新注册用户数
使用场景：渠道投放看板
疑问：退款订单要不要算转化？
```

## 预期输出

```markdown
## 指标口径审查

### 审查结论

当前口径方向可用，但退款、时间窗口和去重规则未定义，直接用于渠道投放看板会带来口径争议。

### 推荐定义

| 项目 | 内容 |
| --- | --- |
| 统计对象 | 新注册用户 |
| 时间口径 | 注册成功时间起 7 个自然日内 |
| 分子 | 7 日内至少一次支付成功的新用户数 |
| 分母 | 统计周期内新注册用户数 |
| 去重规则 | 按 user_id 去重 |
| 退款处理 | 建议分主口径和净转化口径分别展示 |

### 待确认问题

- 注册后 7 天是滚动 168 小时还是 7 个自然日？
- 支付成功后全额退款是否要从主指标中剔除？
- 测试账号、内部账号是否排除？
```

## 使用说明

指标口径一旦进入看板，后续修改成本很高。这个 Skill 应该尽量在开发前使用。
