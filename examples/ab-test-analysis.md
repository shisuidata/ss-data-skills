# ab-test-analysis 示例

## 适用场景

实验结果已经出来，需要判断是否可信、是否可以推广。这个例子展示了 Skill 最重要的价值：**+13.9% 的提升看起来很诱人，但它并不显著**。

## 示例输入

```text
请用 ab-test-analysis 解读这个实验，并生成 HTML 报告：

假设：新版会员页能提高开通转化率
对照组：旧版页面，10000 UV，转化 310
实验组：新版页面，10050 UV，转化 355
护栏指标：退款率、页面加载时间、客服投诉（还没汇总）
周期：7 天，原计划 14 天
```

## 预期输出

Agent 先把输入写成 `summary.json`，运行：

```bash
python3 skills/ab-test-analysis/scripts/ab_test.py analyze --summary summary.json --html ab_report.html
```

然后基于脚本结果输出：

```markdown
## A/B 实验分析

### 1. 结论

暂不能下结论，不建议全量。开通转化率观测提升 +0.43pp（相对 +13.9%），但 p=0.087，未达到显著；护栏指标尚未提供；实验只跑了计划周期的一半。

### 2. 指标结果

| 指标 | 类型 | 对照组 | 实验组 | 变化（pp / 相对） | 95% 区间（相对） | p 值 | 显著 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 开通转化率 | 主指标 | 3.10% | 3.53% | +0.43pp / +13.9% | [−1.9%, +32.4%] | 0.087 | 否 |

### 3. 有效性检查

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 样本比例（SRM） | 通过 | 49.9% / 50.1%，p=0.72 |
| 实验周期 / 整周 | 通过 | 7 天，覆盖一个整周 |
| 提前查看 / 提前停止 | 注意 | 已运行 7 / 计划 14 天，这是中期快照 |
| 护栏指标 | 不通过 | 退款率、页面加载时间、客服投诉均未提供 |

### 4. 如何理解这个结果

当前样本在 80% 功效下只能可靠检测 ≥22.9% 的相对变化。+13.9% 低于这个门槛，所以“不显著”的意思是“这个实验目前还没有能力分辨 +13.9% 和噪声”，而不是“新版无效”。

### 5. 决策建议与下一步

- 按原计划跑满 14 天，不要因中期结果提前停止或全量
- 若真实效应就是 +13.9%，每组需要约 2.69 万样本，按当前流量约需 21 天；请业务方先确认“值得上线的最小提升”，再决定是否延长
- 补齐三个护栏指标后重新运行脚本

### 6. 需要补充的数据

- 退款率、页面加载时间、客服投诉的分组结果
- 实验期间是否有会员促销或版本发布

报告文件：ab_report.html
```

## 使用说明

- 数字以脚本输出为准。人工估算很容易把“+13.9%”当成好消息。
- 实验开始前用 `plan` 子命令算样本量，比事后发现“样本不够”便宜得多。
- 有用户粒度数据和实验前指标时，加 `--cuped` 可以显著缩短实验周期。
- 非均分实验要提供分流比例；按用户分流的点击率用 `clicks/views:ratio`。
- 周期不足或提前查看时，即使主指标显著，脚本也只给 `win_needs_validation`，不会建议放量。
