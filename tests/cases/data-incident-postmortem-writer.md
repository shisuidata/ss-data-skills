# 测试用例：数据事故复盘

## Skill

`data-incident-postmortem-writer`

## 测试目标

检查 Skill 是否能基于事实材料写出清晰的数据事故复盘，包括影响范围、时间线、根因、修复验证、预防措施和对外同步口径。

## 测试输入

```text
请使用 data-incident-postmortem-writer 写一份数据事故复盘。

行业上下文：电商。
事故：经营看板 2026-05-20 的 GMV 比真实值少算约 18%。
发现方式：运营在 2026-05-21 10:20 反馈看板与订单后台不一致。
影响范围：
- 经营日报
- 渠道 GMV 看板
- 类目 GMV Top 10
- 影响 2026-05-20 分区

初步原因：
- 订单明细表新增 pay_status = partial_refund 状态。
- 看板 SQL 只统计 pay_status = success。
- 业务口径要求 partial_refund 订单仍计入支付 GMV，但退款金额应单独扣减。

时间线：
- 2026-05-21 10:20 运营反馈异常
- 2026-05-21 11:10 数据开发定位到状态枚举变更
- 2026-05-21 13:40 修复 SQL 并补数
- 2026-05-21 14:10 业务确认恢复

希望输出：面向数据团队内部复盘，同时给业务方一段同步口径。
```

## 通过标准

- 必须先写事故摘要、当前状态和影响范围。
- 必须用表格或清晰结构还原时间线。
- 必须区分直接原因、深层原因和机制缺口。
- 必须提出可验收的预防措施，例如枚举监控、核心指标对账、上游变更通知。
- 必须给出克制、可复制的业务方同步口径。
- 不得编造未提供的负责人、处罚、影响用户数或金额。
