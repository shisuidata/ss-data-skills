# 测试用例：分析报告写作

## Skill

`data-analysis-report-writer`

## 测试目标

检查 Skill 是否能把 mock 分析事实组织成可决策的业务分析报告。

## 测试输入

```text
请使用 data-analysis-report-writer 写一份分析报告。

报告主题：
2026 年 5 月新用户首购转化率下降分析

目标读者：
业务负责人、产品经理、投放负责人

业务背景：
某电商平台发现 2026 年 5 月新用户首购转化下降。业务希望判断下降是否真实存在，并定位主要原因。

已知事实：
- 对比周期注册用户数 12，支付成功用户数 4，首购转化率 33.3%
- 分析周期注册用户数 12，支付成功用户数 2，首购转化率 16.7%
- 分析周期最大单步流失发生在“浏览商品 -> 加购”
- 分析周期渠道 A 注册用户占比上升到 7/12
- 分析周期支付成功用户主要来自桌面端，移动端支付表现弱

限制：
- 这是 mock 小样本数据，不用于统计显著性判断
- 7 日窗口、退款处理、渠道归因仍需确认

希望输出：
请写成 Markdown 报告，包含执行摘要、核心发现、原因假设、建议动作、风险限制和下一步。
```

## 通过标准

- 先给执行摘要。
- 每个核心发现都要有数据证据。
- 必须说明 mock 小样本限制。
- 不把渠道 A 或移动端问题写成确定因果。
- 建议动作要具体，例如补充埋点、检查移动端加购链路、复核渠道归因。
