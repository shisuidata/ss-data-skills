# 中文业务场景约定

通用可视化规范大多来自英文语境。中文业务报告有一批自己的约定，弄错了读者会直接误读，或者觉得“这不是我们的报告”。

## 数字单位

| 量级 | 写法 | 示例 |
| --- | --- | --- |
| < 1 万 | 千分位原值 | 8,421 |
| 1 万 – 1 亿 | 万 | 1.23万、1269万 |
| ≥ 1 亿 | 亿 | 3.6亿 |

- 面向中文读者不要用 K / M / B。“12.5M” 需要读者心算成“1250万”。
- 金额写清币种和单位：`¥330.6`、`GMV 1269万元`。表头写了单位，单元格就不再重复。
- 同一张表、同一个坐标轴只用一种单位，不要“8,421”和“1.2万”混排。
- `sskit_viz.fmt_num()` 自动按上表压缩。

## 百分比 vs 百分点

比率类指标（转化率、留存率、退款率）的变化有两种说法，必须区分：

- **百分点（pp）**：7.00% → 7.77%，是 **+0.77pp**
- **相对变化（%）**：同一变化是 **+11.0%**

写“转化率提升 11%”会被理解成从 7% 变成 18%。比率类指标的变化，正文优先写百分点，必要时括号补相对变化：“支付成功率 +0.77pp（相对 +11.0%）”。

## 同比与环比

- **同比**：和去年同期比。**环比**：和上一个相邻周期比（日环比、周环比、月环比）。
- **日粒度同比按星期对齐**：今年 5/25（周一）应该和去年的同一个周一比（往前 364 天），而不是去年 5/25。否则周末效应会制造假的涨跌。
- **春节**：春节在公历 1 月下旬到 2 月中旬之间浮动。1 月、2 月单月同比基本不可读，用“1–2 月合并”或“按春节对齐”的口径，并在图注说明。
- **调休**：国内法定假日前后有周末补班，按星期对齐的工作日对比也要检查调休日。
- **大促**：618（预售通常 5 月下旬开始）、双 11（预售通常 10 月中下旬开始）、双 12、年货节。大促期间的同比要确认活动节奏是否对齐，在图上用参考线或阴影标出大促区间。
- **财年**：部分公司的财年不是自然年（例如阿里巴巴财年截至每年 3 月 31 日），报告里写“FY”时要说明起止日期。

## 周口径

- 国内默认**周一开始**。跨年周按 ISO 周（如 2026-W01）还是自然周要统一，并在图注写明。
- “近 7 日”和“本周”不是一回事：前者滚动，后者固定自然周。
- 周报里的“本周 vs 上周”如果本周没结束，要标“截至周 X”。

## 涨跌色

这是最容易出错的地方。两套约定都合理，关键是**明确选一套，并且永远配符号**：

| 约定 | 适用受众 | 规则 |
| --- | --- | --- |
| 好坏色（默认） | 经营、增长、产品、运营 | 颜色表示“好 / 坏”：墨绿=变好，朱红=变坏。退款率下降是变好，用墨绿 |
| 红涨绿跌 | 证券、交易、行情类 | 颜色表示“涨 / 跌”：朱红=上涨，墨绿=下跌，与好坏无关 |

- 用 `sskit_viz.delta_tone(delta, higher_is_better, significant, convention="goodbad" | "market")` 计算颜色语义。
- 永远同时写 ▲ / ▼ 和正负号（`sskit_viz.arrow()`）。红绿两色主要靠色相区分，红绿色弱读者分不出来。
- **不显著或没有被证实的变化不上色**，用中性灰。给噪声上红绿色，会让读者把随机波动当成信号。

## 中文字体

- HTML 报告由浏览器渲染文字，`sskit_viz` 已设置中文字体栈，不会出现方块字。
- 如果必须用 matplotlib 出静态图，先设置字体，否则中文会显示成方块，负号显示异常：

```python
import matplotlib.pyplot as plt
plt.rcParams["font.sans-serif"] = ["PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "SimHei"]
plt.rcParams["axes.unicode_minus"] = False
```

## 标题与措辞

- 图标题写结论：“GMV 同比转负：工作日下滑，周末持平”，而不是“GMV 趋势”。
- 不说“赋能”“抓手”“闭环”等空话；说清楚指标、方向、幅度、原因、动作。
- 时间写全：“2026-05-12 至 2026-05-25”，不写“最近两周”。
