# 有效性检查清单

脚本能自动检查的项目标为【脚本】，其余需要结合业务上下文人工判断。任何一项严重失败，结论都要降级。周期不足、提前查看或停止、提升异常大、样本偏小、护栏未证明在容忍度内时，脚本不会给出 `ship`。

## 1. 分流与样本

- 【脚本】**SRM（样本比例失衡）**：卡方检验 p < 0.001 即判定异常。SRM 意味着某些用户在某一组被系统性地丢掉或多算了，此时所有指标差异都不可信。常见原因：
  - 实验组页面更慢或崩溃，曝光埋点没发出来
  - 分流后又按某个条件过滤（例如只统计“看到新功能的用户”）
  - 机器人流量、缓存、重定向只影响一组
  - 分流哈希的盐与其他实验冲突
- **分析单元与分流单元一致**：按用户分流就按用户统计。按用户分流、按会话统计时，方差会被低估，结果会显得过于显著。
- **比率指标的分母**：人均 GMV 的分母是用户，客单价的分母是订单。订单数本身受实验影响时，客单价的变化不能直接解读。按用户分流的点击率要用 `分子列/分母列:ratio`，脚本按 delta 方法估计方差。

## 2. 时间

- 【脚本】**整周**：工作日和周末用户不同，周期应为 7 的倍数，至少 7 天。
- 【脚本】**提前查看**：在计划周期结束前因为“已经显著”而停止，假阳性率会远高于 5%。如果业务确实需要随时查看，应该在设计时就采用序贯检验，而不是事后看一眼。
- **新奇效应 / 学习效应**：新界面前几天点击率高，之后回落；或者反过来，用户需要时间适应。把结果按天拆开，看效应是否在衰减。
- **外部事件**：实验期间有没有大促、节假日、调休、版本发布、投放大幅变化？外部事件对两组同时生效时不会造成偏差，但会改变效应大小，结论的可推广性下降。

## 3. 指标

- 【脚本】**护栏**：没有护栏数据，不能建议全量。
- 【脚本】**护栏的“没恶化”**：不显著只说明“没检测到”。要证明“没有恶化超过 X%”，需要设置 `max_worsening_rel`，看置信区间的最坏端。
- 【脚本】**多重比较**：主指标越多、实验组越多，偶然显著的概率越大。脚本对主指标做 Holm 校正；辅助指标的显著只能作为参考。
- 【脚本】**结果离谱**（Twyman 定律）：提升超过 30% 时，先查埋点、口径、分流，再庆祝。
- **事后挑分群**：“整体不显著，但新用户 + iOS + 晚上显著”几乎一定是噪声。只解读实验前就定好的分群，并说明分群结论需要独立实验验证。
- **主指标在实验后换了**：看到结果后才决定看哪个指标，属于结果驱动，需要明确指出。

## 4. 干扰与污染

- **网络效应**：社交、双边市场（司机 / 乘客、买家 / 卖家）、库存共享场景中，实验组的行为会影响对照组，普通的用户级随机会有偏。需要按地区、时间片或集群随机。
- **跨端 / 跨设备**：同一用户在不同设备上被分到不同组。
- **同时进行的其他实验**：是否互斥？是否有交互作用？

## 5. 从统计到决策

- 显著 ≠ 重要：+0.05pp 也可能显著，问一句“这个提升值多少钱、上线和维护要花多少钱”。
- 不显著 ≠ 没效果：看最小可检测效应。如果业务关心的效应比它小，这个实验根本没能力回答问题。
- 置信区间的两端都要讲：“最好情况 +27%，最坏情况 −3%”，比“提升 11%”更诚实。
