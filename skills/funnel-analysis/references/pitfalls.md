# 解读要点

## 先排除假象，再讲业务

按顺序排查，任何一项成立都要先修正或降级结论：

1. **口径不是有序漏斗**：后一步人数多于前一步，或者各步独立去重。修正 SQL 后重算。
2. **时期按事件日期切分**：应按入口时间切分，否则跨期转化被截断。
3. **观察期不一致（右截断）**：本期用户刚进来，还没来得及转化。和对比期比之前，统一转化窗口，或排除还没走完窗口的用户。
4. **埋点变更**：跳步用户突然变多、某一步人数断崖式变化，通常是埋点改了，不是用户行为变了。
5. **样本量**：入口用户少于几百时，单步转化率的置信区间很宽，十几个百分点的波动都可能是噪声。

## 读懂两种拆解

**步骤贡献**：整体转化率 = 各步转化率的乘积，所以整体变化可以按对数精确分配到每一步。

- 贡献最大的步骤是优先排查对象，但不一定是唯一问题
- “恢复到对比期水平后整体能回到多少”可以直接换算成挽回的转化人数，适合用于排优先级

**结构效应 vs 转化效应**：

| 结构效应大 | 转化效应大 |
| --- | --- |
| 来了不一样的用户（某渠道、某类设备占比变了） | 同样的用户转化变差 |
| 更像获客问题：投放策略、渠道质量、活动拉新 | 更像产品或流程问题：页面、性能、价格、库存 |
| 找增长、投放团队 | 找产品、研发团队 |

辛普森悖论就藏在这里：每个渠道的转化都没变，整体转化却下降了，原因是低转化渠道的占比上升了。只看整体漏斗会冤枉产品团队。

## 不要做的事

- 只说“浏览到加购流失最多”。漏斗天然逐步流失，要说的是**和对比期相比哪一步变差了**。
- 用人数对比两期。入口规模不同时，人数差异没有意义，要用转化率。
- 把分群差异写成因果。“iOS 转化更高”不等于“iOS 用户更想买”，可能只是 iOS 用户来自更好的渠道。
- 在事后挑出一个显著的分群当结论。分群越多，越容易偶然出现“显著”。
- 停在“某环节下降”。每个判断都要配一个验证动作：看录屏、看错误日志、对比改版时间点、做 A/B 实验。
