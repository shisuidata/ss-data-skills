# Daily Report Writer

## 目标

把一天内零散的数据工作整理成清楚、克制、可同步的日报。

这个 Skill 关注：

- 今天完成了什么
- 对业务或项目有什么价值
- 当前风险和阻塞是什么
- 明天要推进什么
- 哪些事项需要他人协助

## 使用场景

使用这个 Skill，当用户需要：

- 写数据分析、数据开发、BI、治理或项目日报
- 整理 standup 发言稿
- 做跨团队日终同步
- 写值班交接、上线观察或问题跟进日报
- 把零散工作记录整理成可发给主管或项目群的版本

## 不适用场景

不要使用这个 Skill 处理：

- 周报或月报，应使用 `weekly-monthly-report-writer`
- 正式分析报告，应使用 `data-analysis-report-writer`
- 数据事故复盘，应使用 `data-incident-postmortem-writer`
- 没有任何事实材料时凭空写工作成果

## 输入信息

最少输入：

- 日期
- 今天做过的事项列表
- 明天计划

推荐输入：

- 每个事项的状态：完成、进行中、阻塞、待确认
- 产出物：SQL、看板、报告、表、会议结论、问题定位结果
- 影响对象：业务方、项目、指标、任务、表、看板
- 风险和阻塞
- 需要同步或求助的人
- 目标读者：直属主管、项目群、业务方、团队内部

## 写作流程

1. 识别日报读者和发送场景。
2. 将事项按完成、推进中、风险阻塞、明日计划归类。
3. 把动作改写为结果，说明产出和影响。
4. 删除流水账、情绪表达和过细过程。
5. 对阻塞事项写清需要谁做什么。
6. 输出一个可直接发送的版本。默认只给这个版本，读者明确需要结构化表格时再给。

## 输出格式

```markdown
**今日日报 · YYYY-MM-DD**

今日完成
1. <事项>：<产出或结果>，<影响>

进行中
1. <事项>：<当前进展>，下一步 <动作>

风险与阻塞
1. <问题>：<影响>，需要 <谁> 在 <时间> 前 <做什么>

明日计划
1. <事项>

待确认
1. <用户没有提供、需要补充的信息>
```

这个格式可以直接贴进飞书、钉钉或企业微信。没有内容的小节直接省略。

## 按读者调整

| 读者 | 篇幅 | 重点 |
| --- | --- | --- |
| 直属主管 | 200 字以内 | 先结果，再风险和需要的支持 |
| 项目群 | 150 字以内 | 只写和这个项目相关的进展和协作需求 |
| 业务方 | 100 字以内 | 不写技术细节，只写对他们的影响和交付时间 |
| 团队内部 | 不限 | 可以保留表名、任务名和排查细节 |
| 值班交接 | 不限 | 当前状态、未完成事项、下一班要盯什么 |

读者没有说明时，按直属主管处理，并标记这个假设。

## 质量标准

输出必须：

- 基于用户提供的事实，不编造成果
- 把“做了什么”写成“产出了什么”
- 风险和阻塞要可行动
- 语气适合职场同步，避免夸张和邀功
- 按“按读者调整”的规则控制篇幅和重点
- 保留待确认项，不强行写成已完成

## 完成后的下一步

- 汇总成周报或月报：`weekly-monthly-report-writer`
