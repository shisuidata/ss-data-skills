# 解读要点

## 先确认口径

| 问题 | 为什么重要 |
| --- | --- |
| 自然日还是滚动 24 小时？ | 晚上注册的用户第二天早上打开，自然日算 D1 留存，滚动 24 小时不算。两种口径的 D1 常常差几个百分点 |
| 第 N 天当天，还是 N 天内？ | “D7 留存 20%”和“7 日内回访 45%”可能描述的是同一批用户 |
| 回访是什么行为？ | 推送到达、后台唤醒、自动续期扣款都不是主动回访 |
| 批次成熟了吗？ | 注册 3 天的用户没有 D7，留空，不是 0 |

## 曲线怎么读

- **后段趋平**：有一群用户稳定留下来，产品对他们有长期价值。平台高度是最重要的数字。
- **一路下滑到 0 附近**：还没有找到长期价值，或者拉来的用户不对。
- **后段上升**：通常不是好事，先查是不是曲线在不同周期用了不同批次（脚本已固定批次集合），或者有召回活动。
- 曲线必须基于同一组批次。每个周期各用各的成熟批次，长周期只剩早期批次，曲线形状会被批次构成扭曲。

## 批次变差了，先拆构成

最近批次留存下降，常见两种原因：

| 结构效应大 | 留存效应大 |
| --- | --- |
| 低留存渠道、低价套餐、活动用户占比上升 | 同一渠道、同一套餐的用户也留得更差 |
| 找增长和投放：获客质量问题 | 找产品和运营：体验、版本、服务问题 |

异常批次同理：渠道结构变化会让整段时间的批次都“偏低”，真正的事故批次反而淹没在里面。脚本先按分群构成算出预期留存，再判断批次是否异常。

## 不要做的事

- 用“本周活跃用户里的老用户占比”代替留存。
- 把活动期间注册的批次留存高，写成“产品留存改善了”。活动批次要单独看，并看活动结束后的周期。
- 把首日行为和留存的相关写成因果。“首日完成 3 个动作的用户留存高”可能只是因为高意向用户更愿意完成动作。要验证，就把关键动作前置做实验。
- 只看 D1。D1 反映的是首次体验，长期价值要看曲线后段。
